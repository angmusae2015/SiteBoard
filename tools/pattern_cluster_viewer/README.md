# 패턴 클러스터 탐색기

09번의 `PatternClusterer`를 직접 불러오는 로컬 웹 UI입니다. 공통 정제본과 09번 기록을 읽으며 파일을 생성하거나 기존 실험 결과를 변경하지 않습니다. Python 표준 라이브러리만 사용합니다.

## 실행

프로젝트 루트에서 실행합니다.

```powershell
.\.venv\Scripts\python.exe -B tools/pattern_cluster_viewer/server.py
```

브라우저에서 <http://127.0.0.1:8765>를 엽니다. 다른 포트는 `--port 8766`으로 지정합니다. 종료는 실행 터미널에서 Ctrl+C를 누릅니다. 서버는 로컬 주소에만 바인딩합니다.

## 구성과 입력

- `server.py`: 원본 클래스 로딩, 입력 대응 확인, 메모리 캐시와 HTTP API
- `index.html`, `style.css`, `app.js`: 분포 차트, 탐색 목록과 상세 탭
- `dataset/processed/dataset.json`: 클러스터링 대상인 전체 정제본
- `experiments/09/cluster.py`: 정규화, 대표 선택, 유사도와 소속 결정
- `experiments/09/data/cluster.json`: 임계값 0.85의 기준 소속
- `experiments/09/data/work_type.json`: 공종과 규격 규칙
- `experiments/09/data/split_meta.json`, `train.jsonl`, `test.jsonl`: 기존 학습과 평가 유형 및 입력 대응

입력 경로는 프로젝트 루트 기준이며 시작 위치와 무관하게 해석합니다. 서버 시작 시 원천 해시, 0.85 재계산, 현장과 사진 ID 중복, 공종과 규격, 분할 중복과 누락, 메시지 식별자와 원문 및 정답을 확인합니다.

## 조작과 지표

임계값은 0~1이며 0.001 단위로 조정합니다. 슬라이더는 조작 중 200ms 대기 후 자동 계산하며 놓으면 즉시 요청합니다. 요청 중에는 마지막으로 적용한 수치를 유지하고 상태에 계산 중임을 표시합니다. 최신 요청의 결과만 적용합니다. 원본 클래스의 방향별 문자열 유사도와 임계값별 결과를 메모리에 캐시합니다.

트리맵 면적은 전체 레코드 대비 각 클러스터의 건수에 비례합니다. 크기별 막대그래프는 레코드 수 구간마다 클러스터 개수를 집계합니다. 누적 점유율은 크기순 상위 N개 클러스터의 레코드 합계를 전체 레코드 수로 나눈 백분율이며 0.85 기준 곡선과 함께 표시합니다. 상위 10개 점유율은 클러스터가 10개 미만이면 전체 클러스터를 사용합니다. 요약 지표의 증감은 0.85와 비교하며 점유율의 차이 단위는 %p입니다.

검색, 현장, 공종과 크기 구간은 계산이 완료된 전체 결과에서 목록을 필터링합니다. 현장과 공종 필터는 같은 원천 레코드가 두 조건을 모두 만족해야 합니다. 전체 통계와 차트는 전체 데이터 기준을 유지하며 트리맵에서 일치한 클러스터를 강조합니다. 트리맵 선택이 현재 필터 밖에 있으면 필터를 초기화하고 해당 클러스터를 선택합니다.

소속 패턴의 유사도는 대표 문자열과의 `SequenceMatcher.ratio()`이며 소속 패턴 전체 쌍의 최솟값은 아닙니다. 대표와 다른 구간은 문자열의 공통 부분 수열을 기준으로 추가와 삭제를 강조합니다. 정규화 패턴을 펼치면 해당 원문과 정답을 확인합니다. 원문과 정답 탭은 클러스터의 전체 레코드를 표시하며 필터에 맞는 사례를 우선 배치합니다.

클러스터 ID는 임계값마다 다시 부여됩니다. 기준 비교는 원천 인덱스 교집합으로 수행하며 현재 클러스터로 들어온 기준 소속과 각 기준 클러스터가 현재 나뉜 목적지를 표시합니다. 소속 변화순은 기준 클러스터 중 교집합이 가장 큰 대상과의 대칭차 레코드 수 내림차순입니다. 소속 레코드가 같은 클러스터의 ID 변경은 소속 변화로 집계하지 않습니다.

학습과 평가 표시는 09번 고정 분할입니다. 임계값 변경으로 재분할하거나 기존 홀드아웃 ID를 새 클러스터에 적용하지 않습니다. 이 도구는 패턴 분포와 기존 분할을 탐색하며 새로운 학습 정확도를 계산하지 않습니다.
