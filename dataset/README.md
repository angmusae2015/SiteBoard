정제본은 원본에서 (site, image_id) 기준으로 현장 정정 17건을 제외한 자료입니다. 사진 번호를 재부여하지 않습니다. 현장은 BS, DG1~DG4, GJ, HG, JW, SB의 9개입니다.

## 레코드 스키마
`dataset.json`은 사진 단위 객체들의 배열(`Array<Record>`)로 구성됩니다.

```json
[
  {
    "x": "21-벽체D65*2 양면",
    "site": "BS",
    "image_id": 14,
    "y": [
      {
        "workType": "금속관벽체",
        "spec": "65",
        "quantity": 2.0
      }
    ]
  }
]
```

#### 필드 명세
* **`site`** (`string`, 필수): 현장 식별 코드 (`BS`, `DG1`, `DG2`, `DG3`, `DG4`, `GJ`, `HG`, `JW`, `SB`).
* **`image_id`** (`integer`, 필수): 각 현장 내에서 1부터 시작하는 순차 사진 식별 번호.
* **`x`** (`string`, 선택): 보드판 이미지 표의 '내용' 필드 등에 적힌 원본 문자열.
* **`y`** (`array<object>`, 필수): 해당 사진에 기입된 1개 이상의 세부 작업 목록 (사진 1장당 최대 9개).
  * **`workType`** (`string`): 공종 구분 명칭 (반드시 `work_type.json[site]`에 등록된 키).
  * **`spec`** (`string`): 배관 호칭경(`"65"`), 덕트/개구부 치수(`"1200*800"`), 또는 규격 없을 경우 빈 문자열(`""`).
  * **`quantity`** (`float`): 작업 수량 (단면 0.5, 양면 1.0, 2개소 2.0 등).

---

## 현장 정정 사례 스키마 (현장 실사 정정 데이터셋)
보드판 텍스트의 오기입을 현장 관리자가 실제 시공 사진을 판별하여 엑셀에 정정 기록한 17개 불일치 데이터셋입니다. 향후 VLM 비전 교차 검증 및 오기입 탐지 모델의 벤치마크/평가 셋으로 활용됩니다.

```json
[
  {
    "org_index": 180,
    "site": "DG1",
    "image_id": 149,
    "x": "9번 벽체 보 150 100 양면",
    "y": [
      {
        "workType": "금속관벽체",
        "spec": "50",
        "quantity": 1.0
      },
      {
        "workType": "금속관벽체",
        "spec": "100",
        "quantity": 1.0
      }
    ],
    "text_candidate_y": [
      {
        "workType": "금속관벽체",
        "spec": "150",
        "quantity": 1.0
      },
      {
        "workType": "금속관벽체",
        "spec": "100",
        "quantity": 1.0
      }
    ],
    "discrepancy_type": "규격 불일치",
    "reason": "배관 사이즈 육안 확인 후 수정 (150 -> 50)"
  }
]
```

#### 필드 명세
* **`org_index`** (`integer`): `dataset_org.json` 원본 데이터셋 내의 고유 인덱스 번호.
* **`site`** / **`image_id`** / **`x`**: 원본 사진대지 메타데이터 및 보드판 텍스트.
* **`y`** (`array<object>`): 현장 관리자가 사진 실사를 통해 수정한 **최종 실제 시공 정답 레이블**.
* **`text_candidate_y`** (`array<object>`): 보드판 텍스트만 엄격히 파싱했을 때의 가설 레이블.
* **`discrepancy_type`** (`string`): 불일치 유형 (`보온여부 불일치`, `규격 불일치`, `관통방향 불일치`, `수량/마감횟수 불일치`, `누락공종 추가` 등).
* **`reason`** (`string`): 현장 관리자의 실제 정정 근거 및 사유.

## 공종 마스터와 실험별 산출물

공통 work_type.json은 각 기존 실험의 data/work_type.json으로 복사한 뒤 제거했습니다. 이관 시점의 파일을 보존한 것이며 각 과거 실행이 동일 파일을 사용했는지는 별도 검증되지 않았습니다. 과거 실험에 생성 스크립트를 추가하지 않습니다.

기존 마스터는 site → workType → 규격 규칙 형태입니다. 고정 규격은 배열, 규격 없음은 빈 배열([]), 가변 규격은 null로 표현합니다. 공종과 규격은 해당 실험의 마스터와 전수 검증합니다. 향후 데이터에서 마스터를 생성하는 함수와 추출 규칙은 후속 코드 설계 대상입니다.

[실험 색인](../experiments/README.md)에서 실제 데이터 파일과 재현 상태를 확인하세요. 신규 실험의 Qwen 변환본·클러스터·train/test·split_meta는 해당 실험 내부에 생성합니다. 분할 시드와 군집 파라미터는 YAML에, 실제 값·입력 해시·분할 인덱스는 실행 산출물에 기록합니다.

## 데이터 품질 검토

모델의 값 토큰 확률은 오류 검토를 돕는 정보입니다. 높은 값만으로 원본 정답을 오류라고 판단하지 않으며 현장 근거를 함께 확인합니다. 원본 정답과 현장 정정 사유를 보존하고, 정정 사례는 텍스트 학습용 정제본과 구분합니다.

## 유지보수

- 공통 세 JSON의 내용과 정정 사유를 보존합니다. 수정·추가·삭제 시 이 문서의 목록·스키마·이력을 사전 평가 후 갱신합니다.
- 해당 실험의 공종·규격과 ID 고유성, train/test 중복·누락을 검사합니다.
- JSON·JSONL은 UTF-8·ensure_ascii=False로 저장합니다.
- 검사 코드는 일회성 명령으로 실행하고 검증 전용 파일을 남기지 않습니다.
- 표 크롭·OCR은 [도구 안내](../tools/table_ocr/README.md)를 따릅니다. 신규 OCR 결과의 학습 데이터 반영에는 사람 검수가 필요합니다.
