# 07: Qwen3-8B 비추론 랜덤 결합 QLoRA

Qwen2.5-3B를 사용한 06에서 모델 계열과 크기를 Qwen3-8B로 높이고, 지시 프롬프트를 줄인 실험입니다. 같은 현장의 작업기록을 랜덤 결합하며 역빈도 가중치, 공종 빈도 보정과 가중 학습 손실을 사용하지 않습니다. 데이터 분할은 06과 동일합니다.

## 목적과 확인된 내용

목적은 기존의 현장별 작업 텍스트 구조화 문제에서 Qwen3-8B의 비추론 모드와 간결한 지시문, 역빈도 보정 없는 랜덤 결합을 적용하고, 고정 평가 입력에서 공종, 규격과 수량 추출의 성능 및 오류를 확인하는 것입니다. 12GB 데스크톱 GPU에서 4비트 QLoRA 학습과 평가를 완료할 수 있는지도 확인했습니다. 모델 크기만의 효과나 가중 증강 제거만의 효과를 분리하는 통제 실험은 아닙니다.

실제 보존 실행은 [Unsloth 데스크톱 학습](train_desktop_unsloth.ipynb)과 [데스크톱 평가](evaluate_desktop.ipynb)입니다. RTX 4070에서 BF16으로 3에포크 학습을 완료했으며, 완전 일치율은 **90.45% (502/555)**입니다. 익숙한 패턴 94.13%, 홀드아웃 패턴 86.49%, 희소 패턴 77.53%로 희소 유형이 취약했습니다. 출력 JSON 스키마 오류와 출력 상한 도달은 모두 0건입니다.

05의 보존 예측과는 현장 규칙, 보드판 원문과 정답 조합이 중복 건수까지 동일했습니다. 05 대비 정답 26건 증가, 일치율 4.68%p 상승을 확인했으나 학습 분할과 실행 코드가 없는 05와의 통제 비교로 해석하지 않습니다. 수량 계산 개선과 함께 일부 퇴행, 입력과 정답의 불일치 의심 사례를 확인했습니다. 세부 근거와 한계는 [평가 분석](results/README.md)을 따릅니다.

## 프롬프트

시스템 지시문은 다음과 같습니다.

> 보드판 텍스트에서 현장별 허용 공종과 규격 규칙에 맞는 표준 작업 내역을 추출하세요. 설명과 마크다운 없이 JSON 배열만 출력하세요. 각 객체의 필드는 workType(표준 공종명 문자열), spec(규격 문자열, 규격 없으면 ""), quantity(수량 숫자, 부동소수점)입니다.

기존의 작업기록 구조화 목적, 현장별 허용 공종과 규격 제약, 세 필드와 값 타입, 규격 없음의 빈 문자열, JSON 배열만 출력하고 설명과 마크다운을 배제하는 지시를 유지합니다. 현장별 마스터의 항목은 생략하지 않으며 JSON 공백만 줄입니다. 원본 작업 텍스트와 정답 배열도 유지합니다.

Qwen3-8B 토크나이저로 시스템 지시문만 측정하면 06의 207토큰에서 92토큰으로 줄어듭니다. 모델의 공식 채팅 템플릿으로 비추론 프롬프트를 만들고 JSON 응답과 EOS에만 학습 손실을 적용합니다. 템플릿이 넣는 빈 think 구간은 입력이며 생성 정답에 포함하지 않습니다.

## 데이터와 평가 분할

공통 정제본 [dataset.json](../../dataset/processed/dataset.json)에서 07의 클러스터, 분할과 JSONL을 독립 생성합니다. 마스터는 06에 보존된 이관 시점 공통 마스터의 바이트 동일 사본이며 데이터에서 추론하여 생성하지 않습니다.

클러스터 유사도 임계값 0.85, 시드 42, 일반 클러스터 평가 비율 0.18과 홀드아웃 ID `[20, 22, 35, 36, 42, 65]`를 유지합니다. 홀드아웃은 클러스터 전체, 홀드아웃이 아닌 단일 레코드 클러스터는 희소 유형, 나머지는 학습과 seen 평가로 분할합니다. 일반 클러스터의 평가 건수는 `min(n - 1, max(1, round(n * 0.18)))`입니다.

| 구분 | 레코드 수 |
| --- | ---: |
| 전체 | 2,123 |
| 학습 | 1,568 |
| 평가 전체 | 555 |
| seen_patterns | 392 |
| unseen_complex_holdout | 74 |
| unseen_rare | 89 |

231개 클러스터를 생성했습니다. 학습과 평가 인덱스, 평가 유형, 원본 입력 텍스트와 정답은 준비 과정의 일회성 명령으로 06과 전수 대조했습니다. 마스터와 모든 공종 및 규격, 식별자 중복과 분할의 교집합 및 누락도 이때 확인했습니다. 실행 코드에서 같은 검사를 반복하지 않습니다. 홀드아웃은 모든 레코드가 다중 작업이라는 의미가 아니며 현장 전체를 격리하는 분할도 아닙니다.

프로젝트 루트에서 다음 순서로 실행합니다. 현재 데이터는 생성되어 있으므로 기존 파일을 덮어쓰는 재실행은 중단합니다. 보존할 새 실행은 새 실험 ID를 사용합니다.

```powershell
.\.venv\Scripts\python.exe experiments/07/cluster.py
.\.venv\Scripts\python.exe experiments/07/partition.py
.\.venv\Scripts\python.exe experiments/07/build_dataset.py
```

설정 경로는 프로젝트 루트 기준 상대 경로이며 스크립트가 자신의 위치로 프로젝트 루트를 찾습니다. 입력 파일 바이트의 SHA-256을 기록합니다. 줄바꿈만 바뀌어도 해시가 달라지므로 해당 생성 실행의 파일을 함께 보존합니다.

## 데스크톱 학습과 평가

프로젝트 루트의 가상환경과 [requirements.txt](../../requirements.txt)를 사용합니다. 현재 설치된 CUDA PyTorch는 유지하고 프로젝트 의존성을 확인합니다. 새 환경은 CUDA용 PyTorch를 먼저 설치합니다.

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

실제 학습은 Unsloth 경로를 사용했습니다. [일반 학습 노트북](train_desktop.ipynb)은 별도 구성으로 보존하며 해당 경로의 생성 정확도나 Unsloth 대비 속도 차이는 측정하지 않았습니다. Unsloth 실행 환경은 프로젝트 루트의 선택 의존성으로 준비합니다.

```powershell
.\.venv\Scripts\python.exe -m pip install --extra-index-url https://download.pytorch.org/whl/cu128 ".[unsloth]"
.\.venv\Scripts\python.exe -m pip check
```

1. [Unsloth 학습 노트북](train_desktop_unsloth.ipynb)의 커널을 `.venv/Scripts/python.exe`로 선택합니다.
2. 06과 같이 커널의 작업 디렉터리를 `experiments/07`로 설정합니다. 학습의 `prefix_path='./data/'`, 평가의 `prefix_path='data'`가 이 실험의 데이터 디렉터리를 가리킵니다. `train.jsonl`, `models`, `result/run_config.json` 등의 나머지 경로는 `prefix_path` 기준으로 해석합니다. 상단 딕셔너리를 확인하고 위에서 아래로 실행합니다.
3. 첫 모델 로딩 시 고정 revision의 기본 모델과 토크나이저를 내려받습니다. 12GB RTX 4070용 기본값이며 실제 최대 VRAM과 실행 시간은 실행 기록에 저장합니다.
4. 학습 후 GPU 메모리를 해제하거나 커널을 재시작하고 [평가 노트북](evaluate_desktop.ipynb)을 실행합니다. 평가 노트북의 별도 프로세스에서도 같은 CUDA 가상환경을 사용합니다.

노트북은 지정한 JSONL을 읽어 바로 학습과 평가에 사용합니다. 실행 전 데이터 전수 재검사, 토큰 길이 사전 순회와 설정 대조는 하지 않습니다. 실제 학습 샘플이 길이 상한을 넘으면 중단합니다. 학습 중에는 KV 캐시를 끄고, 평가 중에는 켭니다. 학습 검증은 loss만 수집해 전체 어휘 logits를 누적하지 않습니다. 평가에서는 4비트 기본 모델에 어댑터를 연결하며 FP16 전체 모델로 병합하지 않습니다. 기존 모델, 체크포인트, 실행 또는 평가 기록이 있으면 덮어쓰지 않고 중단합니다.

학습 결과는 `data/models/`, 체크포인트는 `data/models/checkpoints/`, 실행 설정과 학습 이력은 `data/result/`에 저장합니다. 학습 설정, 모델 revision, 입력 해시, 라이브러리 버전, 실제 dtype, GPU와 최대 메모리 사용량을 기록합니다. 보존된 실행은 Unsloth 2026.10.9와 transformers.Trainer를 사용했으며, 학습 70.96분, 평가 69.51분입니다. 최대 할당 GPU 메모리는 각각 6.45 GiB, 6.44 GiB입니다. 전체 GPU 사용량이 아닌 PyTorch 할당량이며 예약량 등은 [원본 실행 안내](data/result/README.md)에 기록했습니다.

## Colab

[공통 Colab 안내](../../README.md#google-colab-실행)를 따르되 07 노트북을 사용합니다. 06과 같이 학습 및 평가 입력을 모은 데이터 디렉터리를 `prefix_path`로 지정합니다. 기본값은 06의 경로에서 실험 ID만 바꾼 `/drive/MyDrive/SiteBoard/07/`이며 실제 Drive 위치에 맞게 설정합니다. 프로젝트 전체나 공통 정제본을 학습 런타임에서 다시 읽을 필요는 없습니다. 두 노트북 모두 Drive 연결 셀과 패키지 설치 셀이 있으며 설치 버전 범위는 루트 의존성과 같습니다. BF16을 지원하지 않는 GPU는 FP16을 선택하며 평가도 학습 당시 dtype과 일치해야 합니다.

## 평가 기록과 비교 범위

06과 같은 엄격한 JSON 스키마 채점을 사용합니다. 정확한 세 필드와 값 타입을 검사하고, 문자열 앞뒤 공백과 수량 소수점 넷째 자리 반올림을 정규화합니다. 작업 순서는 무시하고 중복 개수는 유지합니다.

케이스별 원문 예측과 정답, 식별자, 평가 유형, 정확한 일치 여부와 출력 상한 도달 여부를 저장합니다. `workType`, `spec`, `quantity` 값 구간과 겹치는 토큰 확률로 `value_min_confidence`를 계산합니다. 유형별 최소 신뢰도는 정답과 오답을 모두 포함한 케이스 최솟값이며 평균과 구분합니다. 미확인은 `null`과 누락 건수로 남기고 0으로 대체하지 않습니다.

05와 06의 정확도가 비슷했다는 관찰은 [06의 비교 기록](../06/README.md#05번과의-정확도-비교)을 따릅니다. 이번에는 모델 계열과 크기, 프롬프트와 메모리용 학습 설정도 함께 달라지므로 정확도 변화 전체를 모델 크기 하나의 효과로 해석하지 않습니다. 07의 유형은 같은 실험의 식별자와 입력을 검증해 집계합니다. 05는 유형과 식별자가 없어 현장 규칙, 원문과 정답 내용으로 대응했으며 07의 유형을 옮겨 집계하지 않습니다. 모델별 토큰 신뢰도는 보정된 정답 확률이 아닙니다.
