# 실험 색인

각 디렉터리는 다른 실험의 코드·생성 데이터를 참조하지 않는 독립 보존 단위입니다. 먼저 해당 README에서 조건과 보유 자료를 확인하세요.

**00~05 실험은 결과 참고용으로만 사용합니다.** 실험별 사용 데이터셋과 평가 조건이 다르고 누락된 기록도 많으므로, 보존된 점수는 과거 결과를 참고하는 용도로만 해석합니다. 실험 간 직접적인 성능 비교나 변경 효과의 검증, 완전한 재현의 근거로 사용하지 않습니다. 기존 자료와 결과는 그대로 보존합니다.

## 읽는 순서

실험 README → data/(마스터·분할) → results/(평가 기록) → models/(보유 모델) 순으로 필요한 부분만 읽습니다. 과거 실험에는 실제 보유한 자료만 있습니다.

기존 03을 지수별로, 04를 모델 크기와 미확인 QLoRA 설정별로 분리했습니다. 이전 구조 개편에서 코드 통합과 일부 경로 메타데이터 정리가 있었으므로, 남아 있던 공통 코드가 정확한 과거 실행본이라는 근거는 없습니다. 과거 JSON의 내용과 경로 문자열은 원문을 보존했으므로 실행 설정으로 바로 사용하지 않습니다. 기존 설정의 정확한 당시 값과 실행 코드는 미검증입니다.

00~03은 원본 기준 기록, 04 이후는 정제본 기준 기록입니다.

현재 [06](06/README.md)은 학습·평가 노트북 상단의 `RUNTIME_PARAMS`와 `HYPER_PARAMS` 딕셔너리로 파라미터를 관리합니다. 함수에서 두 딕셔너리를 직접 참조합니다. Colab과 데스크톱 실행은 [루트 README](../README.md)를 따릅니다. 06은 균등 파트너 선택으로 학습했으며 [weight_test.ipynb](06/weight_test.ipynb)에서 역빈도 가중치의 노출 분포를 별도로 분석합니다. 06의 모델과 원본 결과는 사용자 요청으로 삭제했습니다. [05번과의 정확도 비교](06/README.md#05번과의-정확도-비교)에 실험자 확인과 삭제 전 대화 분석을 근거로, 역빈도 보정 없이도 전체 정확도가 비슷했던 결과와 검증 범위를 기록했습니다. 신규 조건·보존할 재실행은 새 ID와 독립 사본을 사용하고 기존 산출물을 덮어쓰지 않습니다.

## 평가 기준과 비교 한계

[07](07/README.md)은 06과 같은 분할 전략과 인덱스를 유지하며 Qwen3-8B의 비추론 모드, 역빈도 보정 없는 랜덤 결합과 간결한 지시문을 사용합니다. 실제 보존 실행은 Unsloth 데스크톱 4비트 학습과 일반 데스크톱 4비트 평가이며 실행 중 다른 실험의 코드나 데이터를 읽지 않습니다. 모델 계열과 크기 외에 프롬프트와 메모리용 학습 설정도 바뀌므로 비교 범위를 해당 실험 문서에서 확인합니다.

[08](08/README.md)은 07의 실제 Unsloth 데스크톱 학습과 일반 데스크톱 평가를 기준으로 증강 확률만 0.5에서 0.0으로 바꾸는 대조 실험입니다. 같은 공통 정제본에서 데이터와 분할을 독립 생성하고 07과 메시지 및 메타데이터를 전수 대조합니다. 모델 revision, 프롬프트, 시드 42, 3에포크, 학습 스케줄과 엄격한 채점을 유지합니다. 전체 및 유형별 정확도와 케이스별 개선 및 퇴행을 비교하며, 증강 제거에 따른 토큰 노출 감소를 추가 학습으로 보상하지 않습니다. 단일 시드와 실제 실행 환경의 차이에 대한 해석 범위는 08 문서를 따릅니다.

08의 기존 채점은 07 대비 −14건, −2.52%p이며, 그중 11건의 차이는 실리콘마감 홀드아웃 클러스터 22에 집중됩니다. 합산과 분리 허용은 동일 공종과 규격별 총수량을 비교하는 추가 기준이며 08은 494/555입니다. 원래 점수와 예측은 바꾸지 않습니다. 데이터와 기록의 대응 및 실제 Windows 빌드 차이는 [08 결과](08/results/README.md)에 기록합니다.

[09](09/README.md)는 학습 시드 43, 44, 45에서 같은 고정 평가 555건으로 증강 on/off를 비교했습니다. 기존 기준의 평균 차이는 +0.78%p, 합산과 분리 허용은 +1.20%p이지만 시드별 효과가 일관되지는 않습니다. 특히 가장 큰 개선을 보인 시드 44는 on 평가 배치 1과 off 배치 4 및 평가 구현이 달라 증강만의 차이로 귀속할 수 없습니다. 07과 08의 시드 42 결과는 이 평균에 포함하지 않습니다. 전체와 유형별 건수, 정답 수, 값 토큰 최소 신뢰도 및 클러스터 44 분석은 [09 결과](09/results/README.md)를 따릅니다.

레코드의 공종·규격·수량을 모두 비교하는 완전 일치율을 사용합니다. 작업 순서는 무시하고 중복 개수는 유지합니다. 00~05의 과거 결과는 기존 문자열 파서의 동작을 따릅니다. 06의 현재 평가 노트북은 필수 및 추가 필드와 값 타입을 검사하는 엄격한 JSON 스키마 기준을 사용하므로 과거 채점과 구분합니다. 값 토큰 신뢰도도 실제 정답 확률로 보정된 지표가 아닙니다.

- 비증강과 각 결합 실험의 평가 입력·정답 쌍은 2건이 다르므로 점수 차이를 증강만의 효과로 단정할 수 없습니다.
- 정제 데이터 실험은 평가셋과 모델 크기가 함께 변경되었습니다. 04a(1.5B)와 04b(3B)를 구분합니다.
- 06의 min_weight=1.0은 역빈도 가중치를 모두 1로 만들어 실제 파트너 선택이 균등합니다. 역빈도 가중치 분석에서는 희소 공종과 함께 있는 다수 공종의 동반 증가, 현장 안의 경쟁, 소수 레코드 반복을 확인했습니다. 정확도 개선이나 악화를 입증한 통제 비교는 아닙니다.
- 기존 config JSON은 당시 실행값 전체를 복원한 것으로 검증되지 않았습니다. 특히 04a의 공통 config는 3B 설정이며 1.5B 평가의 실행 설정이 아닙니다.
- 정확한 과거 코드·일부 가중치·기본 모델 revision이 확인되지 않았습니다. 05는 평가 기록이 있으나 당시 분할 파일과 가중치는 없습니다.

00~05의 보존된 결과는 06 노트북으로 재평가한 값이 아닙니다. 실험별 data/의 분할과 인덱스를 유지하고, 새 조건은 새 실험에서 실행합니다. 현재 구현과 운영 조건은 [06 실험](06/README.md#평가-실행)을 참고하세요.

07과 05의 보존 예측은 현장 규칙, 원문과 정답을 내용으로 대응해 동일한 555건임을 확인했습니다. 07은 05 대비 26건을 더 맞혔지만 05의 학습 분할과 당시 실행 코드가 없어 통제 비교는 아닙니다. 05의 유형은 다른 실험의 분할로 보충하지 않습니다. [07 결과 분석](07/results/README.md)에 채점 확인, 개선과 퇴행, 입력과 정답 검토 사례 및 비교 한계를 기록했습니다.
