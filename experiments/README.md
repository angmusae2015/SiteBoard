각 디렉터리는 다른 실험의 코드·생성 데이터를 참조하지 않는 독립 보존 단위입니다. 먼저 해당 README에서 조건과 보유 자료를 확인하세요.

**00~05 실험은 결과 참고용으로만 사용합니다.** 실험별 사용 데이터셋과 평가 조건이 다르고 누락된 기록도 많으므로, 보존된 점수는 과거 결과를 참고하는 용도로만 해석합니다. 실험 간 직접적인 성능 비교나 변경 효과의 검증, 완전한 재현의 근거로 사용하지 않습니다. 기존 자료와 결과는 그대로 보존합니다.

## 읽는 순서

실험 README → data/(마스터·분할) → results/(평가 기록) → models/(보유 모델) 순으로 필요한 부분만 읽습니다. 과거 실험에는 실제 보유한 자료만 있습니다.

기존 03을 지수별로, 04를 모델 크기와 미확인 QLoRA 설정별로 분리했습니다. 이전 구조 개편에서 코드 통합과 일부 경로 메타데이터 정리가 있었으므로, 남아 있던 공통 코드가 정확한 과거 실행본이라는 근거는 없습니다. 과거 JSON의 내용과 경로 문자열은 원문을 보존했으므로 실행 설정으로 바로 사용하지 않습니다. 기존 설정의 정확한 당시 값과 실행 코드는 미검증입니다.

00~03은 원본 기준 기록, 04 이후는 정제본 기준 기록입니다.

현재 [06](06/README.md)은 학습·평가 노트북 상단의 `RUNTIME_PARAMS`와 `HYPER_PARAMS` 딕셔너리로 파라미터를 관리합니다. 함수에서 두 딕셔너리를 직접 참조합니다. Colab과 데스크톱 실행은 [루트 README](../README.md)를 따릅니다. 06은 균등 파트너 선택으로 학습했으며 [weight_test.ipynb](06/weight_test.ipynb)에서 역빈도 가중치의 노출 분포를 별도로 분석합니다. 사용자가 요청한 모델과 원본 결과 삭제를 반영하여 06의 평가 수치를 이 색인에서 재구성하지 않습니다. 신규 조건·보존할 재실행은 새 ID와 독립 사본을 사용하고 기존 산출물을 덮어쓰지 않습니다.

## 평가 기준과 비교 한계

레코드의 공종·규격·수량을 모두 비교하는 완전 일치율을 사용합니다. 작업 순서는 무시하고 중복 개수는 유지합니다. 00~05의 과거 결과는 기존 문자열 파서의 동작을 따릅니다. 06의 현재 평가 노트북은 필수 및 추가 필드와 값 타입을 검사하는 엄격한 JSON 스키마 기준을 사용하므로 과거 채점과 구분합니다. 값 토큰 신뢰도도 실제 정답 확률로 보정된 지표가 아닙니다.

- 비증강과 각 결합 실험의 평가 입력·정답 쌍은 2건이 다르므로 점수 차이를 증강만의 효과로 단정할 수 없습니다.
- 정제 데이터 실험은 평가셋과 모델 크기가 함께 변경되었습니다. 04a(1.5B)와 04b(3B)를 구분합니다.
- 06의 min_weight=1.0은 역빈도 가중치를 모두 1로 만들어 실제 파트너 선택이 균등합니다. 역빈도 가중치 분석에서는 희소 공종과 함께 있는 다수 공종의 동반 증가, 현장 안의 경쟁, 소수 레코드 반복을 확인했습니다. 정확도 개선이나 악화를 입증한 통제 비교는 아닙니다.
- 기존 config JSON은 당시 실행값 전체를 복원한 것으로 검증되지 않았습니다. 특히 04a의 공통 config는 3B 설정이며 1.5B 평가의 실행 설정이 아닙니다.
- 정확한 과거 코드·일부 가중치·기본 모델 revision이 확인되지 않았습니다. 05는 평가 기록이 있으나 당시 분할 파일과 가중치는 없습니다.

00~05의 보존된 결과는 06 노트북으로 재평가한 값이 아닙니다. 실험별 data/의 분할과 인덱스를 유지하고, 새 조건은 새 실험에서 실행합니다. 현재 구현과 운영 조건은 [06 실험](06/README.md#평가-실행)을 참고하세요.
