# 08 데이터와 분할

공통 정제본 `dataset/processed/dataset.json`에서 08의 준비 스크립트로 독립 생성한 입력입니다. 학습 증강을 제외한 07의 조건을 유지합니다.

| 파일 | 내용 |
| --- | --- |
| [work_type.json](work_type.json) | 07에 보존된 이관 시점 마스터의 바이트 동일 사본, 생성 코드 없음 |
| [cluster.json](cluster.json) | 원천 2,123건의 231개 패턴 클러스터와 원천 파일 해시 |
| [split_meta.json](split_meta.json) | 학습 1,568건과 평가 555건의 인덱스, 유형 및 분할 설정 |
| [train.jsonl](train.jsonl) | 원본 학습 메시지와 정답, 증강 없이 사용 |
| [test.jsonl](test.jsonl) | 고정 평가 메시지와 정답, 식별자와 평가 유형 |

클러스터 유사도 임계값 0.85, 시드 42, 일반 클러스터 평가 비율 0.18과 홀드아웃 ID `[20, 22, 35, 36, 42, 65]`를 유지합니다. 평가 유형은 `seen_patterns` 392건, `unseen_complex_holdout` 74건, `unseen_rare` 89건입니다.

준비 시 07과 마스터, 클러스터, 분할 및 모든 메시지와 메타데이터를 전수 대조했습니다. 공통 정제본과 입력 및 정답의 대응, 해당 마스터의 공종과 규격, `(site, image_id)` 중복과 train/test 교집합 및 원천 인덱스 누락 검사도 일회성 명령으로 통과했습니다. 입력과 정답은 보정하거나 재배열하지 않았습니다.

실제 토크나이저와 Dataset을 사용한 일회성 검사에서 학습 1,568건과 평가 555건 모두 원본 메시지 및 정답을 유지하고 증강 파트너 선택이 실행되지 않음을 확인했습니다. 입력과 정답을 합친 최대 길이는 1,122토큰이며 상한 1,280토큰 이내입니다. 노트북의 실행 전 전수 검사로 추가하지 않습니다.

JSON과 JSONL은 UTF-8이며 한글을 이스케이프하지 않습니다. JSONL은 07의 보존 입력과 같은 LF 줄바꿈을 명시해 Windows에서도 동일한 파일 해시를 유지합니다. 준비한 마스터, 클러스터, 분할과 train/test JSONL 5개 파일은 07과 바이트 및 SHA-256이 같습니다. 실행 중 다른 실험의 자료를 읽지 않습니다. 출력 위치는 [models/](models/README.md)와 [result/](result/README.md)를 따릅니다. 기존 파일은 덮어쓰지 않으며 실행 및 비교 설계는 [실험 안내](../README.md)를 따릅니다.

## 완료 후 대응 검증

실제 평가 555건의 (site, image_id, source_index), 입력과 정답을 test.jsonl에 전수 대응했고 test_type은 split_meta.json의 유형별 인덱스와 일치합니다. 현재 정답과 기록된 정답에 차이가 없으며 유형별 건수와 정답 수의 합계는 전체와 일치합니다. 학습과 평가 식별자 중복, train/test 교집합과 원천 인덱스 누락이 없고 원문 및 정답과 마스터의 공종 및 고정 규격도 전수 검증했습니다. 기록된 입력과 어댑터 및 설정 해시는 현재 보존 파일과 일치합니다.

07과의 555건 대응에서도 입력과 정답 및 유형이 모두 일치하며 데이터 5개의 바이트 동일성을 다시 확인했습니다. 08의 기존 점수는 488/555, 합산과 분리 허용 추가 기준은 494/555입니다. [결과 분석](../results/README.md)에 비교와 해석 한계를 기록했고 데이터나 원본 평가 JSON은 변경하지 않았습니다.
